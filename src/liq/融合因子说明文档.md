# 融合因子策略 - 流动性冲击因子 + MPC因子

## 📋 概述

本策略融合了两个独立的因子轨道，形成一个更加稳健的轮动策略：
- **TRACK 1 (流动性冲击因子)**: 基于交易量与价格变化的相对性指标
- **TRACK 2 (MPC因子)**: 基于中间价变化的趋势因子
- **融合层**: 加权组合两个因子信号，支持阈值调仓限制

**回测结果** (截至 2026-03-05):
- 📈 策略年化收益率: **10.95%**
- 📊 基准年化收益率: **8.68%**
- 🔥 年化超额收益率: **2.27%**
- ⚠️ 最大回撤: **-14.66%**
- 🎯 近期超额收益 (2026年): **1.05%**

---

## 🏗️ 架构设计

### 轨道1: 流动性冲击因子 (LIQ)

**核心逻辑:**
```
信号 = (平均收益率 / 平均交易量) 的相对值
LIQ Score = 500指数信号 - HL指数信号
```

**转换过程:**
1. 计算原始信号：`Ret / Volume (滚动40日)`
2. Z-score标准化：`(Signal - Mean) / Std (滚动80日)`
3. 历史分位数：`Signal在过去20日中的百分位排名`
4. Sigmoid映射：`Position = sigmoid(分位数 - 0.5, scale=8)`

**参数:**
- `WINDOW_SIZE = 40`: 计算信号的滚动窗口
- `HISTORY_WINDOW = 20`: 历史分位数参考窗口
- `SIGMOID_SCALE = 8`: Sigmoid曲线的陡峭程度

**仓位含义:**
- 分位数高 → 流动性差 → 减少500仓位，增加HL仓位
- 分位数低 → 流动性好 → 增加500仓位，减少HL仓位

---

### 轨道2: MPC因子

**核心逻辑:**
```
MPC = 中间价的百分比变化 (1日)
标准化MPC = Z-score(MPC, 20日窗口)
信号差异 = 500指数MPC_z - HL指数MPC_z
```

**转换过程:**
1. 计算中间价变化：`ΔPrice / Price (平滑2日)`
2. Z-score标准化：`(MPC - Mean) / Std (滚动20日)`
3. 分位数权重：`Position = 1 - 百分位(信号差异)`
4. 趋势过滤：`MA5 > Close ? 保持权重 : 降仓至60%总仓位`

**参数:**
- `MPC_K_PERIOD = 1`: MPC计算周期
- `MPC_SMOOTH_WINDOW = 2`: 平滑窗口
- `MPC_LOOKBACK_DAYS = 20`: Z-score标准化窗口
- `MPC_MA5_WINDOW = 5`: 趋势均线参考周期

**仓位含义:**
- 信号差异大 → 500表现强 → 增加500仓位
- 信号差异小 → HL表现强 → 增加HL仓位
- 趋势向下 → 整体降仓(总仓位60%)

---

### 融合层: 加权组合

**融合公式:**
```
目标仓位_500 = w_liq × LIQ_Target_500 + w_mpc × MPC_Target_500
目标仓位_HL = w_liq × LIQ_Target_HL + w_mpc × MPC_Target_HL
```

**默认权重:**
- 流动性因子权重: `50%`
- MPC因子权重: `50%`

**调整方式:**
在文件中修改参数即可实时调整：
```python
FACTOR_WEIGHTS = {
    'liq': 0.6,   # 可调整至0-1之间
    'mpc': 0.4
}
```

## 🚦 阈值调仓限制

### 工作原理

**第一步: 计算目标仓位**
- 每日计算两个因子的目标仓位
- 加权组合得到融合目标仓位

**第二步: 检查调仓必要性**
```python
Position_Change = |目标仓位_t - 目标仓位_t-1|

IF Position_Change > ADJUST_THRESHOLD (默认3%):
    触发调仓
ELSE:
    保持当前仓位
```

**第三步: 平滑调仓**
```python
IF 需要调仓 AND 向上调:
    实际仓位_t = min(当前仓位 + (变化幅度 - 缓冲), 目标仓位)
ELSE IF 需要调仓 AND 向下调:
    实际仓位_t = max(当前仓位 - (变化幅度 - 缓冲), 目标仓位)
ELSE:
    实际仓位_t = 当前仓位
```

### 参数配置

| 参数 | 默认值 | 含义 | 调整建议 |
|------|--------|------|----------|
| `ADJUST_THRESHOLD` | 3% | 触发调仓的最小仓位变化 | 降低→调仓更频繁; 提高→更稳定 |
| `POSITION_BUFFER` | 2% | 调仓时的缓冲余地 | 控制调仓幅度的激进程度 |

**调仓统计数据:**
- 总调仓天数: 437天 (66.82%)
- 平均500持仓权重: 50.66% (接近50/50平衡)

## 💡 关键设计特点

### 1. 独立轨道运行
✅ 两个因子完全独立计算，互不影响
✅ 便于单独调试和优化
✅ 提高系统的容错能力

### 2. 加权融合
✅ 灵活的权重配置
✅ 可根据市场情况动态调整
✅ 平衡两个因子的优势

### 3. 阈值调仓限制
✅ 减少过度调仓
✅ 降低交易成本和滑点损失
✅ 提升策略的稳定性

### 4. 平滑调仓机制
✅ 渐进式调整仓位
✅ 避免激进的一步到位
✅ 降低实际执行中的冲击

## ⚠️ 注意事项

1. **数据质量**: 确保输入数据完整无缺失
2. **交易成本**: 默认设置 `COST = 0.0002 (万2)`, 实际情况可根据需要调整
3. **参数合理性**: 
   - 权重应为 [0, 1] 且总和为1
   - 阈值应合理(建议2%-5%)
   - 缓冲应小于阈值
4. **回测偏差**: 历史回测结果不保证复现,未来表现存在不确定性
5. **上线前测试**: 建议在模拟盘充分验证后再上线

## 📞 常见问题

**Q: 两个因子的信号方向是否相反?**
A: 不一定。两个因子衡量的是不同维度的市场特征:
- LIQ衡量流动性相对水平
- MPC衡量中间价的趋势变化
- 两者可能同向也可能反向,融合时会相互平衡

**Q: 如何判断调仓是否过于频繁?**
A: 查看输出的"调仓天数"百分比:
- <30%: 太保守,可降低阈值
- 30%-70%: 合理范围
- >70%: 可能过于频繁,建议提高阈值

**Q: 能否实时更新参数?**
A: 当前版本需要修改代码后重新运行。未来可考虑开发参数配置文件功能。

**Q: 为什么最近(2026年)的超额收益这么小?**
A: 这是正常的波动。市场环境、风格轮换等因素都会影响策略表现。
